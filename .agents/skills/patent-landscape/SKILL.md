# 技术路线与证据知识图谱技能

## 何时使用
用户需要自主发现行业技术问题、前瞻机械研发课题，或已获得专利和论文候选、需要识别高价值发明方向。

## 责任智能体
参考 agents/README.md 中的第 05 号角色；运行环境可以用当前 AI 在同一会话中依次切换专业角色。

## 输入资料
公开科研与行业需求、标准修订、可授权的故障和维保记录、双源证据、机械设计约束、有效工况与用户价值目标。

## 工作流程
1. 分别提取已公开的技术目的、关键部件、系统接口和物理作用机理。
2. 以问题、矛盾、原理、证据、技术特征、验证实验、候选方案作为节点建立来源关系。
3. 标注相互冲突的论文结论、专利技术保护范围和行业标准约束。
4. 按成本、可靠性、性能、可制造性和维保性整理可研究方向。
5. 对未检索到的领域标为覆盖缺口；保留版本和证据引用。

## 必交付成果
技术路线图、问题—方法—证据映射、知识图谱结构和技术空白清单。

## 质量门禁与失败处置
图谱关联分数仅用于研究排序；任何事实关系都要引用已保存的证据 ID。

检索或工具调用失败时保存错误、实际检查范围和后续动作，记录到案卷的质量门禁；未经证实的假设不得当作事实。输出应使用简体中文，保留 DOI、专利公开号、IPC/CPC、技术公式和标准名称的原始准确写法。

## 需求先行：消防车及机械结构课题发现（2026-11-18增补）
1. **建立问题源台账**：优先国家消防救援局年度指南及“揭榜挂帅”榜单、主管部门与标准机构公告、真实事故/维保/FMEA、采购与验收需求、消防人员一线反馈；并行追踪 FAA/EASA/NFPA 等可公开获取的原始资料及跨行业机械故障。每条记录必须保存原始 URL、发布单位、发布时间、观察日期、权威性、适用地区、许可状态、申报截止时间与当前是否过期。
2. **问题抽象**：分离“场景→真实故障/能力缺口→作用机理→现有方法及边界→可测技术指标”，区分权威已证实问题、合理推测问题、前瞻情景。政府课题过期后仍可用于研发选题，但不得当成正在接受申报的项目。
3. **跨领域迁移**：按功能、失效物理与结构拓扑检索工程机械、矿山泵阀、航空地面设备、船舶、石油化工及新能源汽车等，分析借用机理的原始证据、约束差异与潜在专利冲突，结合 TRIZ/FMEA/形态学和 idea-fission 形成多路线候选。
4. **多证据反证**：对每一独立课题调用专利、论文和工业公开信息的原始证据链，明确检索国家/语言/时间、法律状态可用性、同族、权利要求差异、未披露申请风险。搜不到文献仅可标“检索覆盖缺口”，绝不可标“全球尚无人发明”。
5. **价值评审**：以安全/任务影响、实际发生频次、技术效果可测度、可制造性、试验条件、平台复用、成本及权利空间风险分别打分；各分数均带证据和人工审批状态。优先能开展 SolidWorks 参数化建模、ANSYS/流固耦合分析、样机对照试验的机械方案。
6. **问题卡与长期记忆**：每张课题卡要有 problem_id、source_ids、source_published_at、captured_at、mechanism、constraints、target_metric、known_art、inventive_hypotheses、falsification_plan、evidence_gap、status、reviewer，并关联项目独立 SQLite 和 Markdown 文献记忆文件。保密项目的原始技术描述仅在审批后进入外部检索。
7. **交付阶段分离**：默认输出“技术课题/白话概念/候选结构/实验方案”；只有发明人明确申请后才转正式专利申请格式。不得把趋势推演、AI 评分或结构组合直接宣称具备专利新颖性/创造性。
8. **复核与周期性更新**：事件更新、来源变更与检索失效必须留时间戳、版本和错误原因；支持重新打开以往放弃的课题，保存被反证的方案与失败原因，避免上下文压缩后重复研究。

详见 docs/PROBLEM_DISCOVERY.md；本节定义 AI/Skill 研究规范，公开问题源的自动采集和调度仍属于后续代码开发任务。


## 长期课题来源发现优先级（2026-11-19执行协议）

用户要求“自己找题目/研究方向”、跟踪最新行业问题或开始任何消防机械方向查新时，必须先执行：
1. 使用 MCP patent_source_catalog（approved）、patent_topic_catalog、patent_discovery_inbox 读取已有20个来源种子、20个机械课题和增量公告。CLI 可用 mechanical-patent source-catalog sources/topics/inbox。
2. 优先核实来源官网发布日期和更新频率；过期项目保留历史研究价值但不能视为开放申报。平台新增时通过 patent_source_propose 入 pending，AI 不具备 source approve 权限。
3. 对来源观察执行 patent_public_observe，再以专利/论文/跨行业机制、FMEA、TRIZ 导出具体零部件/可测技术效果。通过 patent_topic_derive 形成可回溯的研究假说，并关联可证伪实验。保密研发信息禁止写入公共目录。
4. 对候选先复用 project 文献记忆，然后调用 patent_topic_plan 与既有多源检索、想法裂变、独立反证、工程审查工具；研究笔记必须标明原始 URL、证据缺口、发生时间和可信度，保存为未独立核验状态。
5. 用户选择课题后使用 patent_topic_adopt 转为单项目 SQLite 案卷，保密审批通过后方可对外发送新检索词。未真实执行工程试验时禁止宣称工程已验证或具备专利授权条件。
6. 只批准和处理有明确版权/访问权的公共数据。独立管理员通过本地 CLI 审批新源；AI 可提议但不能自我认证。
详细工作流参见 docs/PROBLEM_DISCOVERY.md，源码 src/mechanical_patent/problem_sources.py，平台和课题种子存于 src/mechanical_patent/data/。
